## Остаточные риски
1. Ссылка = вечный ключ доступа. Нет срока, пароля, лимита скачиваний; пересланную ссылку не отозвать для одного человека — только «Остановить» всё.
2. Нет ограничений на раздающей стороне: число соединений и скорость. Любой, у кого есть ссылка, может выкачивать файл по кругу и забить канал.
3. [ИСПРАВЛЕНО 2026-11-25, по решению владельца — запрет без вопроса: paths::forbidden_share в Node::share (окно и консоль), сравнение папок по идентичности (inode), старые раздачи из запрещённых папок не отдаются, папка TikDL исключается из обхода] share_path принимает любой путь без проверки. Раздача ~ или / идёт без предупреждения; защищает только CSP. Нужно предупреждение для домашней папки, корня диска и системных папок.
4. Белый список включает дочерние хеши. Кто знает ID узла и BLAKE3-хеш известного файла, может проверить, есть ли этот файл в раздачах (низкий риск).
5. Получатель раскрывает свой IP раздающему при «Что внутри?» и при скачивании. В интерфейсе стоит сказать об этом прямо; можно добавить «только через relay».
6. Сборка без подписи (macOS ad-hoc, Windows без подписи) и без автообновления (№20, №21 прошлого аудита). Это главный практический риск: исправление уязвимостей не дойдёт до пользователей.
7. Сайт может многократно открывать tikdl:// и заваливать окно запросами «Скачать?». Нужно схлопывать повторы и ограничивать частоту.
8. Раздачи вечные и идут из трея после закрытия окна. Стоит добавить срок раздачи и, при желании, автостоп через N дней.
