Самое опасное (чужие ссылки, выход за папку, раздача скачанного) закрыто. Остались три группы: доверие к самому приложению, место на диске и честность размеров, удобство.

Состояние на 23.11.2026, после исправлений P0, P1 и переделки интерфейса. Обновлено в 23:45: закрыты места на диске, IP в ссылке, git, состав раздачи; строка меню, перетаскивание, уведомление и https-ссылка сделаны, но ещё не проверены вживую — ниже помечено.

Вопрос: «какие слабые места остались у приложения?»

Суть

Приложение передаёт файлы напрямую между компьютерами по ссылке. Безопасность передачи теперь в порядке, а «внешняя оболочка» — нет. macOS и Windows не узнают в TikDL доверенную программу, исправления не доходят до людей сами. Сама программа не проверяет, хватит ли места на диске, и временно занимает его вдвое. Ниже — по степени вреда.

Слабое местоЧем грозит
закрытоНе было проверки свободного местаЗагрузка 50 ГБ на диск с 20 ГБ свободного дойдёт до конца места и упадёт, забив диск.
закрыто на MacСкачанное временно лежало дваждыСначала данные копятся во внутреннем хранилище, потом выкладываются в папку, а внутренняя копия стирается через ~5 минут. Для 4 ГБ нужно ~8 ГБ свободного.

Что изменилось 23.11, 23:45

  • Место на диске: перед загрузкой приложение сверяет нужное и свободное и отказывает сразу («нужно 464 МБ, свободно 149 МБ») — проверено на маленьком диске.
  • Вторая копия: на Mac файл в папке — «клон» внутренней копии, второго места не занимает (файл 400 МБ занял 411 МБ); внутренняя копия стирается за 15 секунд. На Windows вторая копия на время выкладки остаётся, проверка места это учитывает.
  • IP: в ссылке только ключ узла и посредник — проверено.
  • «Что внутри?» в окне подтверждения: список файлов, точный размер, свободное место — проверено.
  • git заведён, каждый шаг — отдельная запись.
  • Строка меню и перетаскивание в окно — проверены 24.11. Уведомление «Готово» приложение отправляет, но на этом Mac уведомления для TikDL выключены в Системных настройках — баннера не видно, пока их не включить.
  • https-ссылка для мессенджеров — страница-прокладка готова и проверена в браузере; заработает, когда репозиторий будет на GitHub и включены Pages.

Удобство (до исправлений)

  • Ссылки tikdl:// не кликабельны в Telegram, WhatsApp, почте — нужна страница-прокладка в интернете, которая открывает приложение или предлагает его скачать.
  • Нельзя перетащить файлы в окно, выбрать несколько файлов сразу, показать ссылку QR-кодом.
  • Нет уведомления «Готово», нет кнопки «очистить завершённые», папка назначения не запоминается между запусками.
  • Перед скачиванием не виден состав раздачи (какие файлы внутри).

Сам проект

  • Нет истории версий (git). Откатить неудачную правку можно только из ручных копий. Это первое, что стоит завести.
  • Проверки интерфейса (чистота кода, снимки экранов) запускаются вручную, в автоматическую сборку не включены.
  • Проверка стиля кода Rust (clippy) ни разу не запускалась: здесь её не удалось установить.

Что я бы делал дальше — по порядку

  1. Выложить репозиторий на GitHub и включить Pages — заработает https-ссылка.
  2. Подпись, нотаризация и автообновление — когда будут ваши сертификаты.
  3. Срок действия ссылки, счётчик скачиваний.
